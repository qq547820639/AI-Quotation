# 企业采购自动询价 Web 系统 Spec

## Why

企业采购人员创建询价单、联系供应商、回收报价和价格对比的过程人力成本高、耗时长，且报价信息标准化程度低、过程难以追溯。需要一个面向采购人员的可运行前端 Web 系统，覆盖询价单创建、供应商智能匹配、批量发送询价、供应商在线报价、报价统一对比、流程日志和 Excel 导出等完整流程，作为后续接入真实后端的基础。

## What Changes

- 新建 React + TypeScript + Vite 项目骨架，使用 Ant Design 作为 UI 组件库
- 使用 React Router 实现左侧导航 + 顶部工具栏 + 右侧内容区的标准企业后台布局
- 使用 Zustand 管理询价单、供应商、报价等状态，使用 localStorage 持久化草稿与操作结果
- 实现 P0 全部页面与功能：工作台、询价单列表、创建询价单、供应商智能匹配、批量发送询价、供应商报价填报、报价回收状态、报价对比、询价详情、流程日志、Excel 导出
- 实现 P1 部分能力：供应商管理、综合评分、数据图表、草稿自动保存、历史询价复制、物料批量导入
- 生成真实感较强的中文企业采购模拟数据，覆盖已全部报价、部分报价、即将超时、已超时、已完成、已取消、供应商停用、报价金额异常等场景
- 实现统一的配色规范（主色 `#165DFF`、成功 `#00B42A`、警告 `#FF7D00`、错误 `#F53F3F`）与响应式布局（桌面 1440/1280、平板 1024/768）
- 使用 ECharts 动态生成工作台图表，使用 SheetJS 实现 Excel 导出
- 使用 TypeScript 定义 Inquiry、InquiryItem、Supplier、SupplierMatch、Quotation、QuotationItem、InquiryLog、User、Attachment 等数据类型

## Impact

- Affected specs: 无（全新项目）
- Affected code: 全新项目，主要目录包括 `src/pages`、`src/components`、`src/types`、`src/store`、`src/mock`、`src/utils`、`src/layouts`、`src/router`

## ADDED Requirements

### Requirement: 标准企业后台布局
系统 SHALL 提供左侧导航栏 + 顶部工具栏 + 右侧内容区的标准企业后台布局，顶部工具栏包含当前采购组织、全局搜索、待办消息、通知入口、用户头像与个人菜单。

#### Scenario: 桌面端布局
- **WHEN** 用户在 1440px 或 1280px 屏幕访问系统
- **THEN** 显示完整左侧导航栏、顶部工具栏与右侧内容区

#### Scenario: 平板端布局
- **WHEN** 用户在 1024px 或 768px 屏幕访问系统
- **THEN** 左侧导航栏可折叠，核心操作按钮不被隐藏

### Requirement: 工作台
系统 SHALL 提供采购工作台首页，展示本月询价单数量、询价中的单据数量、待处理报价数量、即将超时的询价数量、已完成询价数量、平均报价回收时长、最近询价单列表、待处理任务列表、询价状态分布和近期报价趋势。

#### Scenario: 加载工作台
- **WHEN** 采购人员进入工作台
- **THEN** 展示统计卡片、最近询价单列表、待处理任务列表与 ECharts 图表
- **AND** 突出显示待处理事项和异常提醒（橙色警示）

### Requirement: 询价单管理
系统 SHALL 提供询价单列表页面，支持按编号、主题、创建人、状态、创建时间、截止时间、物料品类筛选与搜索，支持新建、查看详情、编辑草稿、复制、取消、导出。

#### Scenario: 列表筛选
- **WHEN** 用户在询价单列表使用筛选条件
- **THEN** 列表按条件刷新，展示询价单编号、主题、物料数量、邀请供应商数、已报价供应商数、报价截止时间、状态、创建人、创建时间与操作入口

#### Scenario: 超时警示
- **WHEN** 询价单即将超时或已超时
- **THEN** 列表使用橙色警示标识

### Requirement: 创建询价单
系统 SHALL 提供分步骤或分区的创建询价单页面，包含基本信息、物料明细和供应商匹配三个区域。

#### Scenario: 填写基本信息与物料
- **WHEN** 用户填写询价主题、采购组织、币种、报价截止时间等基本信息，并添加多条物料
- **THEN** 系统校验必填字段，自动计算物料总数量，支持保存草稿与预览

#### Scenario: 物料操作
- **WHEN** 用户在物料明细区操作
- **THEN** 支持手动新增、删除、复制物料行、批量导入与从历史询价复制物料

#### Scenario: 离开提醒与草稿自动保存
- **WHEN** 用户在未保存情况下离开页面
- **THEN** 弹出离开提醒
- **AND** 系统在编辑过程中自动保存草稿到 localStorage

### Requirement: 供应商智能匹配
系统 SHALL 根据物料品类、供应商经营范围、历史合作情况和供应商状态推荐供应商，展示供应商名称、等级、主营品类、历史合作次数、响应率、平均响应时间、推荐原因与匹配度。

#### Scenario: 推荐与选择
- **WHEN** 用户进入供应商匹配步骤
- **THEN** 默认展示推荐供应商，支持手动搜索添加、批量勾选、移除、查看详情
- **AND** 对停用或不合格供应商进行禁选提示

#### Scenario: 批量发送确认
- **WHEN** 用户点击一键批量发送询价
- **THEN** 弹出确认弹窗，展示供应商数量和询价截止时间，确认后批量发送

### Requirement: 供应商报价填报
系统 SHALL 提供独立的供应商报价填报页面，供应商可查看询价信息与物料明细，填写物料单价、税率、含税总价、交货周期、质保期限、付款条件等。

#### Scenario: 计算与提交
- **WHEN** 供应商填写报价
- **THEN** 自动计算每项物料金额与报价总金额，支持暂存与正式提交，提交前进行完整性校验

#### Scenario: 超时禁止提交
- **WHEN** 报价截止时间已过
- **THEN** 禁止提交，展示超时提示

### Requirement: 报价统一管理与对比
系统 SHALL 提供报价对比页面，支持以供应商为列、物料为行或以物料为分组展示多个供应商报价。

#### Scenario: 横向对比
- **WHEN** 采购人员打开报价对比页面
- **THEN** 展示含税单价、含税总价、税率、交货周期、可交货日期、质保期限、付款条件、报价有效期、技术偏离、商务偏离、供应商等级、历史合作情况等维度
- **AND** 自动标记每项物料最低价与最快交货供应商
- **AND** 对异常高价或低价进行提示

#### Scenario: 排序与筛选
- **WHEN** 用户在对比页面操作
- **THEN** 支持按总价、交货周期和综合评分排序，支持隐藏未报价供应商、固定物料名称列、横向滚动

#### Scenario: 选择供应商与导出
- **WHEN** 用户选择推荐供应商或多物料分别选择不同供应商
- **THEN** 记录选择结果
- **AND** 支持一键导出 Excel 与生成报价对比摘要

### Requirement: 综合评分
系统 SHALL 提供透明的综合评分机制，评分维度为报价金额 50%、交货周期 20%、供应商等级 15%、历史履约表现 15%，评分逻辑在界面中明确说明。

### Requirement: 询价详情与流程追溯
系统 SHALL 提供询价详情页面，包含基本信息、物料清单、供应商邀请名单、报价回收进度、报价对比结果、附件列表、操作记录与流程时间轴。

#### Scenario: 流程时间轴
- **WHEN** 用户查看询价详情
- **THEN** 展示参考钉钉审批的流程时间轴，记录创建、保存草稿、修改、添加供应商、发送询价、供应商查看、暂存报价、提交报价、报价截止、查看报价、选择供应商、确认结果、取消等节点
- **AND** 每条日志包含操作时间、操作人、操作类型、操作内容、操作结果

### Requirement: 供应商管理
系统 SHALL 提供供应商列表与详情页面，支持搜索、按品类/等级/状态筛选、启用或停用、查看历史报价与合作记录。

### Requirement: Excel 导出
系统 SHALL 使用 SheetJS 实现真实可用的 Excel 导出功能，导出报价对比数据。

#### Scenario: 导出 Excel
- **WHEN** 用户在报价对比页面点击导出 Excel
- **THEN** 生成并下载包含供应商报价对比数据的 .xlsx 文件

### Requirement: 模拟数据
系统 SHALL 生成真实感较强的中文企业采购模拟数据，包含工业交换机、不锈钢法兰、轴承、PLC 控制器、办公电脑、工业润滑油、包装纸箱、安全防护手套等物料，以及上海恒远、苏州联创、宁波华泰、深圳智联、杭州启明、广东正达等供应商，覆盖已全部报价、部分报价、尚未报价、即将超时、已超时、已完成、已取消、供应商合格/停用、报价金额异常、交货周期异常等场景。

### Requirement: 交互状态完整性
系统 SHALL 为所有页面提供完整的交互状态，包括默认、加载、空数据、搜索无结果、表单错误、网络异常、操作成功、操作失败、禁用、无权限状态，关键操作（批量发送、取消、删除物料、移除供应商、确认供应商、提交报价、结束询价）需二次确认，使用统一消息提示组件而非浏览器原生 alert。

### Requirement: 技术栈与工程化
系统 SHALL 使用 React + TypeScript + Vite + React Router + Ant Design + Zustand + ECharts + SheetJS 实现，组件化开发，页面/组件/类型/模拟数据分目录管理，表格支持筛选排序分页批量操作，表单包含完整校验，保证可直接安装依赖并运行。
